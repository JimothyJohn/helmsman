Playground

Write ST. Run it here.

The ST playground is the box's Structured Text compiler and interpreter built for the browser. Write a program, and its VAR_INPUTs and %IX bits become buttons and sliders, its VAR_OUTPUTs and %QX bits become lamps. Run, stop or step it, watch the live diagram and a trend, and tap an output to see why it is on. Nothing is sent anywhere: it all runs in the page.

Stuck? Ask Claude in the side panel with your own Anthropic API key. The key stays in the page (optionally in this browser, if you tick “remember”) and goes only to api.anthropic.com; Claude sees your program and its compile errors and answers with a whole program you can load with one click. It never runs until you press Run.

What it is

The box is the PLC.

Helmsman runs IEC 61131-3 Structured Text modules on a headless edge box. Each module has its own scan rate and its own windows into the process image, and logic names signals rather than addresses: the I/O map binds each signal to a point on a device the box masters, such as a Modbus TCP remote I/O block or the box's own channels. The roadmap adds an agent that drafts modules, an approval step with an engineer's PIN, and a browser canvas that shows the running code as a live diagram; those parts are planned, not built.

  • Devices it mastersRead and write, only through the I/O map. One writer per point.
  • Controllers it observesRead-only. The box reads a CompactLogix's tags; it never writes them.
  • A scanner that owns itThe box is a CIP adapter: the scanner writes assembly 150 and reads assembly 100.

The map of the code and its trust boundaries is docs/ARCHITECTURE.md; the plan is TODO.md.

Most open CIP stacks are adapters, the device end that answers requests. helmsman-proto is the other end: it finds devices, reads their attributes over TCP 44818 and opens Class 1 connections that exchange I/O over UDP 2222 at a fixed requested packet interval (RPI). The workspace ships the adapter side too, so both ends run without hardware.

Command line

Build it, point it at a device.

cargo build --release

# ListIdentity broadcast
target/release/helmsman discover

# Identity object, attributes 1-7
target/release/helmsman identity 10.0.0.50

# any attribute, class.instance.attribute, printed as hex
target/release/helmsman get 10.0.0.50 0xF5.1.5

# Class 1 exclusive-owner connection
target/release/helmsman io 10.0.0.50 --config 151 --out 150 --in 100 \
    --out-len 32 --in-len 32 --rpi 50 --set 0102...

helmsman help lists every flag. io binds UDP 2222 locally, because targets send their input data there.

Runtime

Modules on a scan.

helmsman-plc runs one or more Structured Text modules, each with its own scan period and its own %I, %Q and %M windows. Two modules may not drive the same output byte. With --io-map, a module's VAR_INPUTs and VAR_OUTPUTs bind to named signals; a module whose inputs are missing is held with its outputs at their safe values rather than computing on stale data.

An instruction budget bounds every scan, so an endless loop is a watchdog fault, not a hang. A fault zeroes that module's outputs and stops only it; the adapter stays on the network so the box can still be found. PLCopen XML projects (ladder and FBD from Beremiz or the OpenPLC Editor) run too; --emit-st shows the Structured Text they lower to.

Ships as a systemd unit for a Raspberry Pi (deploy/helmsman-plc.service).

PROGRAM blink
VAR count : INT; END_VAR
  count := count + 1;
  %QX0.0 := count MOD 2 = 0;
  %QW1 := INT_TO_WORD(count);
END_PROGRAM
