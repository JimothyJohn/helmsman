Getting a machine running used to mean hours of setup before the first useful line: installing the software, starting a project, chasing syntax errors, then working out how each device talks and wiring up the comms by hand.

Helmsman is a new way to program a machine: you talk to it. It is good at the part of controls work nobody enjoys, like finding how a device talks, bringing the link up and mapping the I/O. Your time goes to what the machine should do, and to checking that it does it.

  • No licence fees

    Helmsman is open source under Apache 2.0. Use it on as many machines as you like.

  • A $30 controller

    The Skipper is an off-the-shelf board powered over its Ethernet cable. It needs little to hook up and makes it easy to spread control across a line.

  • Plug in and go

    The editor runs in a browser on any computer and the program runs on the device. Plug it into an Ethernet switch and start.

Your device talks to ours. Helmsman learns how each device talks once, proves it on a real unit and publishes it in a public device library. From then on it recognises that device on any network and adds it to a project in one click.

Standards and interoperability

Built on open standards

Helmsman speaks the protocols your equipment already uses and keeps the program in a standard language, so nothing is locked into a proprietary format. It also hides the hard parts: you say what a device does, and Helmsman handles how it talks.

  • IEC 61131-3

    Programs are standard Structured Text that other tools can read. Projects from other tools come in as PLCopen XML.

  • EtherNet/IP

    Runs remote I/O and drives. The PLCs you already have see Helmsman as a standard device, and it reads their tags without ever writing to them.

  • Modbus TCP

    Runs remote I/O blocks and devices directly, with every point given a name you can read.
