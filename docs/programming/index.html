Programming

Specs, not code

Tell Helmsman what the machine should do in plain language. Helmsman drafts the program, and you check how it behaves.

How it works

Describe, visualize, approve

  1. Describe

    State the sequence step by step, with its interlocks and alarms, the way you would explain it to a colleague. Drop in what you already have: a written spec, a drawing as a PDF, a photo of the panel, or a program exported from another PLC.

  2. Visualize

    Watch the draft behave on a live diagram, with the values on the wires, running against a simulation of your I/O. Tap any output to see exactly what drives it.

  3. Approve

    Nothing goes live until it is approved. Each requirement you state becomes a test, and a failing test holds the change back.

Under the diagram

The code is there when you want it

Underneath, every program is standard IEC 61131-3 Structured Text. You can open it, compare it between versions and take it to another controller. Most of the time you won't need to: the live diagram is what tells you whether the machine does the right thing.

There is no ladder. Ladder was made so electricians could read relay circuits; a diagram with live values shows the same thing to anyone on the floor.

Already have a program?

Bring it along

Hand Helmsman an export from your current tools, such as a Rockwell L5X file or a PLCopen XML project, and it reads the tags and the logic before it writes anything. Helmsman only ever reads your existing PLCs. It never writes to them.

After it is live

Every change, kept

  • History

    Every change says what it changed, who made it and when. Step back through the whole history and bring back any earlier version.

  • Simulation first

    Try a change against the simulated machine before anyone approves it, so the real one only sees what already worked.

  • Your devices

    Helmsman finds the devices on your network and looks each one up in the device library, so the I/O is mapped for you.
